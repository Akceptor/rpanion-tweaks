# AGPS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Pi service that, at every FC/GPS boot, injects "enable AssistNow Autonomous + UTC time + approximate position" into the u-blox M10 through ArduPilot. It caches the last good fix on the Pi and logs time-to-first-fix.

**Architecture:** `python/agps.py` connects to mavlink-router TCP `127.0.0.1:5760` as sysid 1 / compid 193. It watches HEARTBEAT and GPS_RAW_INT from 1/1 and, after a settle delay, sends UBX frames wrapped one-per-message in `GPS_INJECT_DATA` to 1/1. ArduPilot writes those bytes unchanged to the GPS UART. Pure functions (UBX framing, message builders, source selection, cache) sit apart from a `Runner` state machine driven by a fake connection in tests.

**Tech Stack:** Python 3.11 (Pi OS Bookworm; no newer syntax), stdlib + `pymavlink` (ardupilotmega dialect, as in `requirements-dev.txt`), `unittest`, systemd.

**Spec:** `docs/superpowers/specs/2026-10-29-agps-design.md`

## Global Constraints

- Nothing about location leaves the vehicle. Only targeted `GPS_INJECT_DATA` to 1/1. Nothing broadcast. No coordinates in logs, STATUSTEXT or the repo. Tests use `47.0, 8.0` (as Lima does).
- One UBX frame per `GPS_INJECT_DATA` (never split; raise if > 110 bytes). Frames ≥ 100 ms apart. `GPS_INJECT_DATA`, never `GPS_RTCM_DATA`.
- VALSET: only `CFG-ANA-USE_ANA` (`0x10230001`) = 1, layers RAM+BBR (`0x03`). Don't touch `CFG-ANA-ORBMAXERR`.
- Time only when `timedatectl show -p NTPSynchronized --value` == `yes`. tAcc 1 s, leapSecs 18, ref 0.
- Position order: cache (age ≥ 0 and ≤ `AGPS_CACHE_MAX_DAYS`=14 d, posAcc `AGPS_CACHE_ACC_KM`=25 km) → manual `AGPS_APPROX_LAT/LON[/ALT_M]` (posAcc `AGPS_APPROX_ACC_KM`=50 km) → none.
- Cache `/var/lib/agps/last_fix.json`: `{"lat","lon","alt_m","t"}`, lat/lon rounded to 2 decimals, mode 0600, atomic replace. Written only from GPS_RAW_INT fix ≥ 3 with nonzero lat/lon: first fix, then at most every 900 s. `AGPS_CACHE=0` → no read/write, delete file.
- Timing: settle `AGPS_SETTLE_S`=15 s after first GPS_RAW_INT `fix_type ≥ 1`. Already fix ≥ 3 → VALSET only. One resend after 30 s if no 3D fix. FC heartbeat gap > 10 s → start over.
- Settings exactly as in the spec table. `AGPS_ENABLE=0` → exit 0. Invalid numeric setting → exit 2 with a stderr message. Invalid manual lat/lon → warning, treated as unset.
- Repo style: plain functions/classes, comments only for real traps, tests load the script by path (`tests/agps_loader.py` like `tests/lima_loader.py`), run with `.venv/bin/python -m unittest discover -s tests -v`.
- Don't edit `python/video-server.py` (conflicts with PR #6) or `python/lima.py`.

## Review Focus

1. FC reboots while the Pi stays up (heartbeat gap > 10 s, then GPS_RAW_INT fix 1 again) → the full bundle is sent again. Test in Task 4.
2. Service restarted while the GPS already has a 3D fix → only VALSET is sent, no TIME or POS. Test in Task 4.
3. Cache file empty, corrupt, or with `t` in the future (Pi clock was wrong when written) → ignored, falls back to manual, no crash. Test in Task 2.
4. GPS_RAW_INT `fix_type=3` with lat/lon `0` (some FCs report this briefly) → not cached and doesn't count as a fix. Test in Task 4.
5. Messages from other sysid/compid (e.g. a GCS, or our own echo) don't drive the state machine. Test in Task 4.

### Task 0: Feasibility spike (on the Pi, ~10 min, user runs it)

No repo changes. Proves that injected UBX reaches the M10 and finds its firmware version. **Stop the plan if it fails.**

- [ ] **Step 1:** User, on the Pi with FC powered:

```bash
sudo -u rpanion python3 - <<'EOF'
import time
from pymavlink import mavutil
m = mavutil.mavlink_connection('tcp:127.0.0.1:5760', source_system=1, source_component=193)
m.wait_heartbeat(timeout=10)
poll = bytes.fromhex('b5620a0400000e34')  # UBX-MON-VER poll
m.mav.gps_inject_data_send(1, 1, len(poll), poll.ljust(110, b'\0'))
end = time.time() + 5
while time.time() < end:
    s = m.recv_match(type='STATUSTEXT', blocking=True, timeout=1)
    if s: print(round(time.time() - end + 5, 2), s.text)
EOF
```

### Task 4: Runner state machine

**Files:**
- Modify: `python/agps.py` (`Runner`)
- Test: `tests/test_agps_runner.py` with a `FakeConn` exposing `.mav.gps_inject_data_send(ts, tc, n, data)` that records calls, plus pymavlink message objects built from `ardupilotmega.MAVLink_heartbeat_message` / `MAVLink_gps_raw_int_message` with `_header.srcSystem/srcComponent` set (helper `msg(cls, src=(1, 1), **fields)`)

**Interfaces:**
- Consumes: Tasks 1–3.
- Produces: `class Runner(conn, settings: Settings, cache: FixCache, clock=time.monotonic, wall=time.time, ntp=ntp_synced)`
  - `handle(msg) -> None`: ignores anything not from 1/1. HEARTBEAT updates last-seen and `armed` (`base_mode & MAV_MODE_FLAG_SAFETY_ARMED`). GPS_RAW_INT updates fix state. A "good fix" is `fix_type >= 3` with nonzero lat and lon.
  - `tick() -> None`: drives the states `WAIT_GPS → SETTLING → SENT → DONE` from the Global Constraints timings. Sends each frame of `build_assist` through `to_inject` → `conn.mav.gps_inject_data_send(1, 1, n, data)`, spaced 0.1 s apart (injectable `sleep`). Writes the cache. Logs `agps: sent valset[,time][,pos=<source>]` and `agps: first 3D fix <s>s after GPS detected`, with no coordinates.
  - `state: str` for tests.
