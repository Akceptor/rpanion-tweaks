# Lima Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A MAVLink proxy on the Pi that shows the rover in Lima, Peru on the ground station map, while commands from the GCS still drive the real rover correctly.

**Architecture:** `mavlink-routerd` (run by Rpanion) gets one UDP output pointing at Lima instead of at the GCS. Lima parses every packet with pymavlink. Downlink positions are moved to Lima and uplink positions are moved back, both in metres around an anchor taken from the first 3D GPS fix. Lima forwards only packets on an explicit pass list or that it converted. Everything else is dropped.

**Tech Stack:** Python 3 (stdlib + `pymavlink`, ardupilotmega dialect, MAVLink 2), `unittest`, systemd.

**Spec:** `docs/superpowers/specs/2026-10-26-lima-design.md`

**Setup before Task 1:** create worktree `.worktrees/lima` on new branch `lima` from `main` (superpowers:using-git-worktrees). The spec and this plan are untracked in the main checkout. Move both into the worktree and commit them as the first commit (`docs: Lima design and plan`).

## Global Constraints

- Fail closed: a real coordinate never reaches the GCS. If Lima can't classify or convert a packet, the packet is dropped.
- No real coordinates in the repo, including tests. Tests use the real-side point `47.0, 8.0` and the fake anchor `-12.0700, -77.0435`.
- Fake anchor default `-12.0700,-77.0435` (Campo de Marte, Lima).
- Anchor = first `GPS_RAW_INT` with `fix_type >= 3` and nonzero lat/lon. Persisted at `/run/lima/anchor.json`, mode `0600`.
- Round-trip error: ≤ 1 unit on `degE7` int fields, ≤ 1 m on float-degree fields.
- Uplink guard: drop a converted target farther than `LIMA_MAX_TARGET_KM` (default `5`) from the latest real position. With no real position yet, drop it.
- AMSL altitude passes through unchanged.
- Settings: `LIMA_FAKE_ANCHOR` (default `-12.0700,-77.0435`), `LIMA_LISTEN` (default `127.0.0.1:14580`), `LIMA_GCS` (required, `ip:port`), `LIMA_MAX_TARGET_KM` (default `5`), `LIMA_ANCHOR_FILE` (default `/run/lima/anchor.json`, mainly for tests).
- Runs as user `rpanion` and uses the pymavlink the Rpanion `.deb` installs for that user.
- Don't build the on/off toggle. All conversion goes through one `Rewriter` object so a toggle can wrap it later.
- Match repo style: plain functions and classes, few comments (only for real traps), `unittest` tests that load the script by path like `tests/test_battery.py`.
- Tests run with `.venv/bin/python -m unittest discover -s tests -v`.

## Review Focus

1. Rpanion restarts `mavlink-routerd`, so the router's source port changes. Uplink must go to the newest router address, not the first one seen. Test in Task 5.
2. Joystick or velocity-only `SET_POSITION_TARGET_GLOBAL_INT` (position bits masked out, lat/lon 0) must pass with no guard drop. Test in Task 4.
3. Mission Planner can send MAVLink 1 frames. Converted packets must go back out as v1 with the same sysid, compid and seq. Test in Task 3.
4. Lima restarts with an empty or corrupt `/run/lima/anchor.json`. It treats this as no anchor, takes a fresh one, and doesn't crash. Test in Task 3.
5. One UDP datagram can hold several MAVLink packets, or garbage bytes. Each packet is handled on its own and garbage is dropped. Test in Task 3.

**Interfaces:**

### Task 5: UDP loop, entry point, systemd unit

**Files:**
- Modify: `python/lima.py` (net + `main`)
- Create: `systemd/lima.service`
- Test: `tests/test_lima_net.py`

**Interfaces:**
- Consumes: `Rewriter`, `AnchorStore` (Tasks 1–4).
- Produces:
  - `run(listen: tuple[str, int], gcs: tuple[str, int], rewriter: Rewriter, stop: threading.Event) -> None`: a single-threaded `select` loop. Socket A is bound to `listen`, receives from the router, and remembers the newest source address. Socket B is bound to an ephemeral port and sends to `gcs`. It accepts packets only from `gcs`'s IP. Downlink output goes to `gcs`, uplink output to the newest router address (dropped if none yet). Warnings go to `gcs` after each uplink.
  - `parse_hostport(s: str) -> tuple[str, int]`, `parse_latlon(s: str) -> tuple[float, float]`
  - `main() -> None`: reads the settings from Global Constraints. A missing or invalid `LIMA_GCS` exits with code `2` and a stderr message. Logs `Lima: anchor set` (no coordinates) once anchored.
